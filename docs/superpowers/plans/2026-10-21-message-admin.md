# 消息管理后台实现与验收

> 使用 executing-plans 在当前任务实现，最后独立代码审查。

**目标：** 按已确认的 Amie 设计，在 `/admin/` 查询真实任务、执行和消息；原 Agent 界面保留。

**结构：** Web handler → 现有 MySQL DAO；工具请求和结果沿用已有消息记录，模型调用边界补存请求上下文、工具定义和原始响应分片。前端原生 HTML/CSS/JS，放入 Web 的 `管理系统` 目录，不增加框架、接口抽象或独立服务。

**约束：** Go 不使用 if 初始化语句；ID 全部以字符串返回浏览器；只读查询；原始消息不改写；旧记录缺少请求时明确提示。

## 重点边界

1. 超过 JavaScript 安全整数的任务和消息 ID 必须完整往返。
2. 工具在不同 Run 中复用调用 ID 时不能串联。
3. 多页结果中焦点消息必须出现，过滤不能隐藏未加载内容而误称没有结果。
4. 子任务树不能混入其他任务；闭环或大量记录不能让查询无限运行。
5. 用户内容和工具 JSON 只能以文本显示；切换查询时旧请求不能覆盖新结果。
